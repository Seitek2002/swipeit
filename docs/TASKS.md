## Как работать (вставить Исполнителю один раз, перед первой задачей)

Ты — Исполнитель проекта SwipeIt. Ты пишешь фронтенд: Next.js + TypeScript + Tailwind v4 + zustand + TanStack Query, архитектура FSD. Сервера пока нет: всё работает на мок-сервере поверх localStorage.

Перед первой задачей прочитай:
1. `docs/PRD.md` — что и зачем мы делаем.
2. `docs/TECH_SPEC.md` — архитектура, модель данных, мок-сервер. **Это контракт: отклоняться можно только с объяснением.**
3. `docs/DESIGN.md` и открой в браузере `docs/design/reference.html` — как это должно выглядеть и двигаться.
4. `../imbir-nextjs/docs/CODESTYLE.md` целиком (включая анти-паттерны) и бегло `../imbir-nextjs/docs/ARCHITECTURE.md` — стиль кода и структуру берём оттуда.

Правила:
- Одна задача — один законченный кусок. Не забегай вперёд в следующие задачи. Если для текущей нужно что-то из будущей — сделай минимальную заглушку и напиши об этом.
- Задача сдана, когда `npm run check` и `npm run build` проходят без ошибок, а все пункты «Готово, когда» выполнены и проверены руками в браузере на ширине 390px.
- Проверяй глазами: открой приложение в браузере (скилл `agent-browser` или Chrome), пройди сценарий задачи, сделай скриншоты ключевых состояний в `docs/progress/<номер задачи>/`.
- У тебя нет настоящих телефонов. Там, где в критериях написано «телефон» или «другое устройство», используй **отдельный профиль браузера или инкогнито с чистым хранилищем** и эмуляцию мобильного экрана с тачем. Для режима `lan` открывай сетевой адрес ноутбука (`http://192.168.x.x:4000`), а не `localhost`. То, что можно проверить только на настоящем телефоне (ощущение жеста, установка PWA, Wi-Fi), отмечай в PROGRESS.md пунктом «Нужна проверка владельцем на телефоне: …».
- После каждой задачи допиши в `docs/PROGRESS.md` блок:
  ```
  ## T05 — Онбординг и профиль — ✅ сдано / ⚠️ с оговорками
  Что сделано: …
  Отклонения от ТЗ и почему: …
  Вопросы к PM: …
  Скриншоты: docs/progress/T05/
  ```
- Тексты интерфейса — по разделу 9 DESIGN.md. Не придумывай новые цвета, шрифты и радиусы — только токены.
- Не меняй файлы в `docs/` кроме `PROGRESS.md`, `progress/` и `DEMO.md` (T19). Если считаешь, что в ТЗ ошибка, — напиши в «Вопросы к PM» и сделай самым разумным способом.
- Коммить после каждой сданной задачи (репозиторий инициализируешь в T01). Начиная с T02b — сразу `git push` в `origin main` и проверка, что деплой на GitHub Pages прошёл и сайт работает. Только этот репозиторий, без `--force`, без переписывания истории.

### Задача T12b — Режим «Локальная сеть»

**Цель:** владелец запускает одну команду на ноутбуке, друзья открывают адрес на своих телефонах в той же Wi-Fi и тестируют вишлисты, брони, а дальше Планы и Санту с живыми людьми.

**Читать:** TECH_SPEC §1, §6 («Определение режима», «Изоморфность»), §7, **§7a целиком**; DESIGN.md §8.10–8.11.

**Сделать:**
1. `frontend/lan/`: `server.ts` (статика из `out/` через `sirv`, `/api/*` → те же `routes.ts` мок-сервера, `/ws` на `ws`), адаптеры `file-db.ts` (атомарная запись, очередь), `ws-realtime.ts` (рассылка + онлайн), `fs-catalog.ts`. Запуск через `tsx`, свой `lan/tsconfig.json` с алиасом `@/*`.
2. Скрипт `npm run lan` (`next build` → сервер), флаги `--reset` и `--port`. Вывод в терминал: адреса, QR, подсказка про брандмауэр Windows и гостевые сети, предупреждение про публичные Wi-Fi.
3. Клиент: `shared/api/mode.ts` по-настоящему определяет режим; `httpTransport` с `x-user-id`; WebSocket-реализация `Realtime` с переподключением и инвалидацией всех запросов после него; сверка часов с сервером.

5. Друзья: «В этой сети» (люди, онлайн по `/presence`) и «Демо-друзья» (боты). Все люди сервера — друзья друг другу автоматически.

7. Отличия интерфейса в `lan` из DESIGN.md §8.11: плашка в онбординге, индикатор в демо-панели, тост потери связи и неактивная колода во время обрыва, скрытая кнопка системного «Поделиться», копирование через запасной вариант, без service worker.

**Готово, когда:**

- Телефон А отправляет вишлист, телефон Б бронирует подарок — у А счётчик меняется без перезагрузки.
- Останавливаешь сервер на 10 секунд (или включаешь режим «Офлайн» в DevTools) → тост «Нет связи с ноутбуком…» → запускаешь → «Снова в сети», данные актуальны.
- Перезапуск сервера без `--reset` сохраняет все данные; с `--reset` — чистая база.
- Та же сборка `out/`, выложенная на обычный статический хостинг (или `npx serve out`), работает в режиме `local` без ошибок в консоли.
- Скриншоты обоих телефонов — в `docs/progress/T12b/`.
