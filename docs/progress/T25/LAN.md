Дата: 27.11.2026, 21:50–22:20 (Бишкек). Проверял субагент QA. Код не менял, ничего не коммитил.

**Стенд.**
- Сервер — `npm run lan -- --reset` из `frontend/`. Адрес из баннера: `http://192.168.68.100:4000`.
- Два «телефона» — сессии agent-browser `lanA` (Тимур) и `lanB` (Алия), обе 390×844. Обе открыты по LAN-адресу, не по localhost: так, как откроют настоящие телефоны.
- Нажатия — `click`, `find … click` и `eval`. Свайп вправо — настоящим протягиванием мышью (`mouse down/move/up`).

**Важная оговорка про стенд.** В 21:56, пока шла проверка, папку `frontend/out` пересобрал другой процесс на машине. Новая сборка была с `NEXT_PUBLIC_BASE_PATH=/swipeit`, как для GitHub Pages. После этого каждая новая страница с LAN-сервера висела на прелоадере: все `/swipeit/_next/*` отдавали 404.

Что я сделал:
- сохранил чужую сборку;
- собрал свою с пустым `NEXT_PUBLIC_BASE_PATH`, скопировал её во временную папку и вернул чужую сборку в `frontend/out`;
- дальше поднимал тот же `createLanServer` из `frontend/lan/server.ts` с `outDir`, указывающим на копию. База — та же `frontend/.lan-data`, `serverId` тот же: телефоны остались теми же пользователями.

Код сервера тот же, отличается только папка со статикой. Сценарии 1–3 начаты на «чистом» `npm run lan`, остальные — на этом запуске. После проверки `.lan-data` восстановлена из резервной копии: в ней снова данные, которые были до проверки.

## Дефекты

### Заметно

**Д1. Ссылки и QR с ноутбука ведут на `localhost` — на телефонах не откроются.**
- Шаги: `npm run lan` → открыть на ноутбуке адрес, который печатает баннер («На этом ноутбуке: http://localhost:4000») → создать план → «Позвать ещё» → «Скопировать ссылку».
- Ожидалось: `http://192.168.x.x:4000/plans/join/?id=…` — адрес, который откроет телефон в той же Wi-Fi.
- Получилось: `http://localhost:4000/plans/join/?id=pl_w9YZgn6QTk`. QR, ссылка вишлиста и приглашение в Санту строятся так же, от `window.location.origin`.
- Подозреваемые файлы:
  - `frontend/src/shared/lib/dom/share-targets.ts:8` — `shareUrl` берёт `window.location.origin`;
  - `frontend/lan/server.ts` — `printBanner` советует localhost.
- Вариант решения: в режиме `lan` брать адрес сети из `GET /health`, а в баннере не предлагать localhost для отправки ссылок.
- Скриншот: `lan-27`.

**Д2. На телефонах в «Локальной сети» нет кнопки «Поделиться».**
- Шаги: открыть приложение по `http://192.168.x.x:4000` → «Отправить вишлист» → шаг отправки.
- Ожидалось: по задаче три иконки — «Поделиться / Скопировать ссылку / Показать QR».
- Получилось: две — «Скопировать» и «QR». По http-адресу сети страница не в безопасном контексте (`isSecureContext === false`), поэтому нет ни `navigator.share`, ни `navigator.clipboard`.
- Копирование при этом работает: запасной путь через `execCommand`, тост «Ссылка скопирована», в буфере верный LAN-адрес. На `localhost` (безопасный контекст) все три иконки на месте.
- Так и заложено в TECH_SPEC (стр. ~768, «нет `navigator.share` → кнопку не показываем»). Но на тесте с друзьями «Поделиться» не будет ни у кого — стоит предупредить в `docs/DEMO.md`, раздел 2.
- В той же строке TECH_SPEC ещё перечислены «Telegram, WhatsApp» — этих кнопок в интерфейсе уже нет, документ отстал.
- Файлы: `frontend/src/shared/lib/dom/share-targets.ts`, `docs/TECH_SPEC.md`.
- Скриншоты: `lan-06` (LAN-адрес), `lan-27` (localhost).

### Мелочь

**Д3. Иконки «Позвать по ссылке» на экране игры Санты до прокрутки наполовину под плавающим таб-баром (390×844).**
- Шаги: экран игры, игра ещё не разыграна.
- Ожидалось: кнопка целиком видна и нажимается.
- Получилось: кнопка «Скопировать ссылку» занимает y = 744…800, таб-бар начинается примерно с 768. Клик в центр кнопки попал в таб «Вишлист» — открылся вишлист. Пользователь, скорее всего, прокрутит, но нижняя половина иконки «мёртвая».
- Подозреваемое место: нижний отступ страницы игры (`frontend/src/pages`/`widgets` Санты) относительно высоты таб-бара.
- Скриншот: `lan-26`.

**Д4. «Ты здесь первый — позови друзей», хотя в сети уже есть человек.**
- Шаги: A открыл приложение и ещё не назвался → B открывает приложение.
- Ожидалось: B видит, что в сети уже кто-то есть.
- Получилось: «Ты здесь первый», хотя `GET /presence` уже отдаёт двоих онлайн. Люди без имени отфильтрованы.
- Это может быть задумано (без имени человека не покажешь), но текст тогда неправдив. Вариант: «Здесь уже 1 человек» без имени.
- Файл: `frontend/src/entities/user/ui/NetworkPlaque.tsx:24`.

**Д5. В «Новый план → Кто идёт?» и «Новая игра → Кто играет» живые люди из сети в общем списке с ботами, в конце.**
- Ожидалось: DEMO.md: «участники — из «В этой сети»». Логично показать людей сети первыми или отдельной группой, как в «Друзьях».
- Получилось: Алия — последняя после 8 демо-ботов, без пометки. В демо-базе ещё есть бот «Тимур», и тёзку-человека легко перепутать.
- Файлы: экраны создания плана и игры (`features/plan-create`, `santa-create`).

**Д6. `frontend/README.md` устарел.**
- В разделе «Тест с друзьями по Wi-Fi»: «Пройди короткое знакомство — и ты в игре», «Телефонам придётся снова пройти знакомство».
- Знакомства (анкеты) с этапа 7 нет: сразу лента, имя спрашиваем при действии. В `docs/DEMO.md` текст уже правильный.

**Д7. `npm run lan` раздаёт общую папку `frontend/out`, которую перезаписывает любой `next build`.**
- Шаги: во время работы `npm run lan` собрать сборку для Pages (`NEXT_PUBLIC_BASE_PATH=/swipeit`).
- Получилось: уже открытые вкладки работают, но новые загрузки висят на прелоадере: все ассеты отдают 404. Сервер этого не замечает.
- Для владельца на тесте с друзьями это маловероятно. Для параллельных проверок агентами — реальная ловушка, на ней споткнулась эта проверка.
- Вариант: сервер при старте проверяет, что в `out/index.html` нет чужого `basePath`, или LAN-сборка лежит в своей папке.
- Файл: `frontend/lan/server.ts` (`outDir`, `hasBuild`).

## Наблюдения (не дефекты)

- Брони ботов. Через пару минут после отправки боты-друзья забронировали 3 из 5 желаний A. Для теста с живыми друзьями это мешает: свободных подарков остаётся мало. Можно перед тестом выставить ботам «скорость» в демо-панели.
- Заголовок `x-user-id` в сети не проверяется: любой участник может запросить `GET /api/me/dates` с чужим id и получить чужие даты (id видны в `/presence` и `/friends`). Так заложено в TECH_SPEC («сеть доверенная»), но пусть это будет записано в README рядом с предупреждением про публичные сети.
- «Решено: Каток — Суббота, 28 ноября в 12:00» для плана «Прямо сейчас» — по TECH_SPEC (ближайшая суббота 12:00).
- Первый клик agent-browser по «Забронирую я» в гостевом вишлисте не срабатывал: кнопка была у нижнего края, под плавающей плашкой. После прокрутки к центру сработала. Похоже на особенность инструмента, а не на дефект — ручная проверка на телефоне подтвердит.

## Что не удалось проверить

- **Настоящие телефоны, Wi-Fi и брандмауэр.** Обе сессии — Chromium на том же ноутбуке. Обращение по LAN-IP (`192.168.68.100`) проверено, но не с другого устройства. Нет проверки iOS Safari, реального касания и вибрации.
- **Выключение Wi-Fi на одном телефоне.** Вместо этого останавливал сервер. Клиентская часть одинаковая (обрыв WebSocket), но обрыв сети на одном устройстве — другой путь: таймауты, а не закрытие сокета.
- **Скриншот тоста «Снова в сети».** Тост живёт около 3 секунд, кадр не попал. Факт показа подтверждён логом DOM в обеих вкладках (22:18:07–22:18:10).
- **«Поделиться» на телефоне.** В безопасном контексте её не будет никогда (Д2); на localhost кнопка есть, но системный лист шаринга в headless не открывается.
- **Режим плана «До даты» и голосование «Выбрать самим» по сети** — не входили в сценарии.
- **Чистый `npm run lan` от начала до конца.** Из-за пересборки `out/` другим процессом (см. «Стенд») сценарии 3–7 шли на том же коде сервера, но со статикой из моей копии сборки.
