### S01. Пакет администратора B18 — проверен в CI, без сервера — Высокий

**Кто:** Исполнитель, сейчас. Само развёртывание — администратор по готовому ADMIN.md.

**Почему.** BACKEND §1.4: первая версия готова, когда два телефона проходят сценарии через интернет (B21). Для этого нужен staging (B18), а B18 стоит как «ждёт администратора». На деле от администратора нужен только сервер. Пакет, миграции, бэкап, восстановление и откат можно собрать и проверить в GitHub Actions: там Docker есть, а на машине Исполнителя он падает. Сейчас первое развёртывание сломается: в образе нечем применить миграции (`build.mjs` не собирает `migrate-cli.ts`, `server.ts` миграций не запускает).

**Сделать:**
- **Миграции в образе.** `build.mjs` собирает ещё `dist/migrate.js` из `db/migrate-cli.ts`. Папка миграций в образе уже есть.
- **`backend/deploy/docker-compose.yml`:**
  - `migrate` — одноразовый контейнер (`node dist/migrate.js`); `api` ждёт его через `depends_on: condition: service_completed_successfully`;
  - `api`: **одна копия** (хаб WebSocket, планировщик, лимиты и счётчики ошибок живут в памяти процесса), `restart: unless-stopped`, healthcheck на `/v1/health`, том для `UPLOADS_DIR`, ротация логов Docker на 14 дней (§10.1, §12). Тег образа — `API_TAG` из `.env`;
  - `postgres:17-alpine` без `ports` наружу, свой том;
  - `backup` — раз в сутки `pg_dump` в сжатом виде и архив папки фото в том `backups`. Хранение — 14 ежедневных и 8 еженедельных копий (§10). Шифрование и выгрузка к другому провайдеру включаются переменными (`BACKUP_ENCRYPT_KEY`, `BACKUP_S3_*`). Без них — только локально, и в логе предупреждение;
  - `caddy` — отдельным профилем (`--profile caddy`), на случай, если у администратора нет своего прокси с HTTPS.
- **`backend/deploy/scripts/`:**
  - `backup.sh`;
  - `restore.sh <файл> [база]` — восстанавливает в **отдельную** базу (по умолчанию `swipeit_restore`) и печатает число строк по каждой таблице рядом с рабочей базой.
- **`backend/deploy/.env.example`** — каждая переменная из `config.ts` с пояснением по-русски: `DATABASE_URL`, `PUBLIC_SHARE_URL`, `PUBLIC_APP_URL`, `CORS_ORIGINS`, `TRUST_PROXY`, `OPS_TOKEN`, `MIN_CLIENT_BUILD`, `RATE_*`, `UPLOADS_DIR`, `COMMIT`, `API_TAG`, `BACKUP_*`.
- **`backend/deploy/ADMIN.md`** по-русски, для человека, который не читает код:
  - требования: ОС, Docker с Compose v2, 2 ГБ памяти, 10 ГБ диска, порты;
  - установка, обновление (`docker compose pull && docker compose up -d` — миграции применятся сами), откат (`API_TAG=<прошлый тег> docker compose up -d api`; миграции только добавляющие, §11.3);
  - бэкапы: где лежат, как восстановить, проверочное восстановление раз в месяц;
  - прокси: пример nginx для HTTPS и `/v1/ws` (`Upgrade`, `Connection`, `proxy_read_timeout 75s`) и `X-Forwarded-For` вместе с `TRUST_PROXY` (R01);
  - «Отчёт для владельца» (R02): `docker compose exec api node dist/funnel.js --days 7 --live` и `GET /v1/ops/report` с `OPS_TOKEN`;
  - мониторинг `/v1/health` раз в минуту;
  - «staging — боевой для офиса»: базу не сбрасывать, нагрузочный B20 — отдельным проектом (`docker compose -p swipeit-load`);
  - вопросы администратору из B18 п. 3 и из R02: кто запускает `exec`, можно ли открыть `/v1/ops/report` наружу.
- **CI** (`.github/workflows/deploy.yml`, новая задача `deploy-smoke` после `backend`):
  - собрать образ;
  - `docker compose up -d` с тестовым `.env`, дождаться `/v1/health`;
  - создать профиль и 5 «Хочу» через `curl`;
  - `node dist/funnel.js --days 1 --live` в контейнере;
  - `backup.sh` → `restore.sh` → числа строк совпадают;
  - откат: поднять `api` с другим тегом (вторая сборка с другим `COMMIT`) → `/v1/health` показывает его коммит.

### S02. Фронт и API с одного адреса — без Cloudflare — Высокий

**Кто:** Исполнитель, сейчас. Домен или поддомен даёт администратор (§14.3).

**Почему.** Фронт продукта (`remote`) пока выложить некуда: Cloudflare Pages ждёт секретов с 27.11. Превью коротких ссылок с адреса фронта ждёт того же (B16). Если тот же сервер отдаёт и статику, и API, всё упрощается:
- пилот зависит от одного человека — администратора, а не ещё и от Cloudflare;
- CORS не нужен;
- `/s/<код>` сразу живёт на адресе продукта;
- администратору проксировать один адрес, а не два.

Cloudflare Pages остаётся на потом: тогда `/s/*` переедет в функцию, как в §6.3.

**Сделать:**
- **`NEXT_PUBLIC_API_URL=same-origin`.** Особое значение в `shared/api/remote-base.ts`: адрес API — `window.location.origin`, WebSocket — `wss://<тот же хост>/v1/ws`. Тогда одна сборка работает на любом домене, и домен не вшит в образ. Тест `remote-base`.
- **Контейнер `web`** в `backend/deploy/docker-compose.yml` (Caddy на 8080 по HTTP, а с профилем `caddy` — сам с HTTPS):
  - `/v1/*`, включая `/v1/ws`, и `/s/*` → `api:4100`;
  - остальное — статика `frontend/out` (сборка `remote`, без `NEXT_PUBLIC_BASE_PATH`) с `try_files` для экранов-папок (`/w/`, `/santa/join/`…);
  - кеш: `/_next/static/*` — `immutable`, `sw.js` и HTML — `no-cache`;
  - **не** ставить `Cross-Origin-Opener-Policy: same-origin`: с ним не работает окно входа Telegram (§3.3).
