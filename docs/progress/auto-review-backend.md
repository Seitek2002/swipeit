# Ревью сервера (B05–B09), субагент, 28.11.2026

Субагент прочитал серверный код по BACKEND.md §2.6, §3, §4.2–4.6, §6. Пункты R1–R4 и R6 он воспроизвёл на тестовой базе. Отметки о сделанном — в [PROGRESS.md](../PROGRESS.md).

## High

**R1. Владелец узнаёт, кто бронировал: безымянный друг «появляется» в момент брони** (§4.6 п. 1, §4.3)
- Сценарий:
  - Гость без имени открывает `/share/<код>` — дружба ставится сразу, но в `/friends` у владельца безымянных не видно.
  - Гость бронирует с именем «Айгерим». В тот же момент у владельца счётчик броней становится 1, а в «Друзьях» появляется «Айгерим».
- Где: `guest/handlers.ts` (дружба при открытии; имя из формы брони — в профиль), `friends/handlers.ts` (`/friends` скрывает безымянных).
- Исправление: при открытии ссылки дружить только посетителю с именем. Безымянному — доступ по коду, без дружбы.

## Medium

**R2. Гонка «Забронирую я» и «Мне это подарили»: открытая бронь на подаренном желании.** Бронь читает желание без блокировки. Исправление: желание читать `FOR SHARE` — бронь дождётся «подарили» и увидит статус `given`.

**R3. Взаимоблокировка в `makeFriends` → 500.** Двое одновременно открывают вишлисты друг друга: строки дружбы вставляются в разном порядке, Postgres ловит deadlock. Исправление: вставлять пару в одном порядке (меньший `user_id` первым).

**R4. Хаб событий копит все события в памяти навсегда.** `delivered.push` без чистки в рабочем сервере. Исправление: по умолчанию хаб ничего не хранит, копит только тестовый.

## Low

**R5. Брони по старым ссылкам: id пользователя можно проверить на существование.** Для несуществующего `u_X` — 200 и бронь под `ext:u_X`, для чужого существующего — 403. Исправление: снимок старой ссылки — только `ew_…`/`ext:…`; любой `u_…` — как настоящий пользователь.

**R6. «Отменить» после второго «подарили» → 500.** Undo открывает все брони, закрытые за 10 минут, и упирается в уникальный индекс. Исправление: «подарили» закрывает брони одной меткой времени и запоминает её; undo открывает только их.

**R7. Ссылка «Где купить» с любой схемой** (`javascript:`). Исправление: только `http(s)://`.

**R8. Нет лимитов на размер части полей** (не подтверждено):
- `requestId` ссылки-фильтра (уходит в уникальный индекс);
- `at` в «подарили»;
- число ключей `variantChoice`;
- рост `dismissedReminders`.

Исправление: ограничения в схемах core.

Проверено без нарушений:
- права и 404 в `/users/:id`, `/users/:id/wishlist`, `/reservations`;
- `request` в ответе на ссылку-фильтр — только автору;
- повод для других — без названия даты;
- уникальные индексы §4.2;
- лента и свайпы — как в моке.
